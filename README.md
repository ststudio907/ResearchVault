# ResearchVault

An Obsidian plugin that turns your vault into a **research operating system**: manage research projects, track papers, capture quotes from your sources, and keep everything as plain Markdown in your vault.

## Features

- **Projects** — Create, switch, and delete research projects. Each project is a folder (with `papers`, `notes`, and `literature` subfolders) whose contents are filtered into the sidebar view. Exactly one project is active at a time; the **Manage projects** command handles switching, creating, and deleting from one place.
- **Paper tracking** — Add papers manually, by pasting CSL-JSON (e.g. from Zotero or a DOI resolver), or by DOI through the built-in citation lookup (Crossref and OpenAlex). Papers are stored as Markdown files with structured frontmatter: authors, year, DOI, citekey, reading status, priority, and bibliography. Citekeys only need to be unique within a project, so the same paper can be added to multiple projects under the same citekey.
- **Shared PDF library** — Attach a PDF to a paper; the plugin copies it into one vault-level library folder (default `Research Vault/pdfs`, configurable in settings) and wikilinks it from the note. Add the same paper to a second project and, when it matches by DOI (or by title, first author, and year), the existing PDF is linked instead of copied — you'll see a confirmation line in the import form and can override it. Per-project `pdfs/` folders from older versions keep working.
- **Quote capture** — Select text in the editor and run **Capture quote** to append it to a paper's note as a blockquote quote card with tags.
- **Projects sidebar** — A dedicated view lists your projects and papers, filters by status/priority, and offers fuzzy search over paper titles, authors, and citekeys.
- **Citation lookup** (opt-in) — Resolve DOIs and search strings against Crossref and OpenAlex to prefill the paper-import form. Responses are cached in memory for up to 30 days (configurable); reloading the plugin clears the cache.
- **Zotero sync** (opt-in) — Pull items from your Zotero library into the paper-import form using your account ID and read-only API key.
- **Zotero push** (opt-in, desktop only) — Push a paper's metadata into a running Zotero desktop instance via its local connector (`127.0.0.1:23119`). Nothing leaves your machine.
- **Templates** — Customize the Markdown templates used for new papers and notes in **Settings → ResearchVault**.
- **BibTeX export** — Run **Export bibliography (BibTeX)** to rebuild `<project>/bibliography.bib` from your paper notes: publication-grade fields (volume, issue, pages, publisher, entry type), citekey-sorted, byte-stable across re-exports. An existing file that wasn't generated by ResearchVault prompts before it is overwritten, so hand edits are never clobbered silently.
- **Cite while you write** — Run **Insert citation** to fuzzy-pick a paper from the active project: Enter inserts `[@citekey]` (parenthetical), Shift+Enter inserts `@citekey` (inline, for "As @key show, …"). These markers render as **style-formatted citations** — `(Jones, 2019; Smith & Jones, 2020)` for a `[@a; @b]` group, `Smith & Jones (2020)` for a narrative `@key` — in both reading view and live preview (source mode always shows the raw markup), computed by a built-in CSL engine (citeproc) with the project's citation style, entirely offline, still clickable to the paper note. Turn off **Render styled citations in reading view** to keep the plain links. The markup stays the Pandoc citation convention — compile notes plus your exported `.bib` to formatted citations plus a reference list in any CSL style (APA, IEEE, …) via `pandoc --citeproc`. See [Exporting to Word or PDF](#exporting-to-word-or-pdf-pandoc) below for the one-click flow.
- **Word/PDF export** (desktop) — Compile the active note with your locally installed pandoc and `--citeproc` into a formatted `.docx` or `.pdf` next to the note, using a per-project citation style. See [Exporting to Word or PDF](#exporting-to-word-or-pdf-pandoc).
- **Sidebar copy actions** — Each paper row offers **Copy BibTeX entry** and **Copy citekey**.
- **Works offline by default** — All network features are opt-in and off until you enable them in settings.

## Installation

### Beta (BRAT)

ResearchVault is currently in beta. The easiest way to install the beta is with the [BRAT](https://github.com/TfTHacker/obsidian42-brat) plugin:

1. Install and enable **BRAT** from the community plugin browser.
2. Run **BRAT: Add a beta plugin for testing** and enter `ststudio907/ResearchVault`.
3. Enable **ResearchVault** under **Settings → Community plugins**.

Once it's in the community catalog, it will be installable directly from **Settings → Community plugins → Browse**.

### Manual

1. Download `main.js`, `manifest.json`, and `styles.css` from the latest release.
2. Copy them into `<Vault>/.obsidian/plugins/researchvault/`.
3. Reload Obsidian and enable the plugin under **Settings → Community plugins**.

## Getting started

1. Run **Create research project** to make your first project.
2. Run **Add paper** to log your first paper — use DOI lookup or CSL-JSON paste to skip manual typing, and attach the PDF straight from the form.
3. Add the same paper to another project: its PDF in the shared library is linked automatically, with no duplicate copy.
4. Select text in any note and run **Capture quote** to attach it to a paper.
5. Click the library ribbon icon (or run **Open sidebar**) and pin the view to your sidebar for day-to-day browsing.

## Exporting to Word or PDF (pandoc)

Turn a finished note into a formatted document with citations resolved against your project's bibliography. Everything runs locally through **a pandoc binary you install yourself** — the plugin bundles nothing and never downloads anything.

### One-time setup

1. **Install pandoc** (the plugin cannot do this for you):
   - macOS (Homebrew): `brew install pandoc`
   - macOS/Windows/Linux installers: [pandoc.org/installing](https://pandoc.org/installing/)
2. **Optional, PDF only**: install a LaTeX engine (e.g. MacTeX, TeX Live, or MiKTeX). Word export does not need it.
3. Check **Settings → Research Vault → Citations → Pandoc binary**. The default `pandoc` works when the binary is on your system PATH; if Obsidian can't find it, put the full path there (e.g. `/opt/homebrew/bin/pandoc` on Apple-silicon Macs, `C:\Users\you\AppData\Local\Pandoc\pandoc.exe` on Windows). For bare names the plugin also probes the standard Homebrew locations as a fallback.

### Exporting a note

1. Open a note that lives **inside a project folder** (the project's `bibliography.bib` supplies the citations) and contains `[@citekey]` markers (see [Cite while you write](#features)).
2. Run the command **Export note to docx/PDF (pandoc)**.
3. In the dialog, pick a **citation style** (pre-filled from the project's default; `custom` accepts the vault path to any `.csl` file) and an **output format**. Tick **Save as project default** to make this style the project's future default.
4. The document is written **next to the note** (e.g. `Papers/my-note.docx`), and Obsidian opens a confirmation dialog with a **Show in folder** button that reveals the file in Finder/Windows Explorer.

Notes:

- The export first rebuilds `bibliography.bib` from your paper notes. If a hand-edited bibliography is detected you'll be asked whether to overwrite it — declining is safe; the existing file is used as-is.
- PDF export fails with pandoc's own error if no LaTeX engine is installed; use `.docx` if you don't need PDFs.
- Word documents are plain files on disk, but **Obsidian's file explorer hides `.docx` by default**. Either use the **Show in folder** button, or enable **Settings → Files & Links → Detect all file extensions** to see them in the sidebar.
- Mobile: the export command is desktop-only and hidden on mobile.

## Privacy & external services

ResearchVault runs locally and makes **no network requests** until you explicitly enable one of the opt-in integrations below. There is no telemetry, no auto-update, and no remote code execution.

- **Citation lookup** (off by default, under **Settings → ResearchVault → Citation lookup**) sends only the DOI or search string you typed to `api.crossref.org` and/or `api.openalex.org`. No vault content is sent. Responses are cached in memory for up to 30 days (configurable), avoiding repeat requests while cached; reloading the plugin clears the cache. The optional polite-pool `mailto:` contact is off by default and, when enabled, is sent only to your chosen provider.
- **Zotero sync** (off by default, under **Settings → ResearchVault → Zotero sync**) sends only library read requests — plus your search terms — to `api.zotero.org`, using the account ID and read-only API key you provide. No vault content is sent. The API key is stored locally in this vault's plugin settings file.
- **Zotero push** (off by default, desktop only) sends a paper's metadata (title, authors, year, DOI, abstract) to the Zotero desktop app running on the same computer, via Zotero's local connector server on `127.0.0.1:23119`. All traffic stays on your machine. The push button appears only when Zotero is actually running.
- **Word/PDF export** (desktop) makes **no network requests at all**: it runs the pandoc binary installed on your machine against files in your vault, writes the output into the vault, and — for the "Show in folder" button — asks the operating system to reveal that file in your file manager.
- **Styled citations** run entirely inside Obsidian: the CSL engine (citeproc-js) and the vendored CSL styles/locales ship inside the plugin and make **no network requests**. Your notes are never modified — the raw `[@citekey]` markup stays on disk exactly as written.

## Development

```bash
npm install
npm run dev           # watch-bundle into main.js (no type-check)
npx tsc --noEmit      # type-check the plugin
npx tsc --noEmit -p tests/tsconfig.json  # type-check tests
npm run build         # one-shot production bundle (writes main.js + size report)
npm run analyze       # alias for build; also writes esbuild-metafile.json
npm run lint          # eslint with eslint-plugin-obsidianmd
npm test              # vitest unit tests
npm run deploy        # copy main.js/manifest/styles.css into a local test vault
```

The build emits `main.js` at the repo root; copy it alongside `manifest.json` and `styles.css` into `<Vault>/.obsidian/plugins/researchvault/`, then reload Obsidian.
